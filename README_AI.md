# UjinFizteha — React, React Bits, Telegram и MCP

## Запуск

Нужны Node.js 22.12+ и Python 3.8+. В корне репозитория:

```bash
npm ci
npm run build
python app/run.py
```

Откройте http://127.0.0.1:8787/web/. Python раздаёт собранный React из
`app/web/dist`, дополнительных серверов в production-режиме не требуется.
Без сборки сервер возвращает сообщение с командой `npm run build`.
Для доступа в доверенной локальной сети добавьте `--host 0.0.0.0`.

Для разработки запустите Python на порту 8787 и отдельно `npm run dev`.
Vite проксирует `/api` к Python. React-исходники находятся в `frontend/src`.
Обновление `frontend/src` требует новой сборки для Python-сервера.

## Новый интерфейс

Тёмный dashboard, три главных раздела: «Мой дом», «Сценарии», «История».
Пятнадцать эмуляторов: розетка, свет, термостат, вентиляция, температурный датчик, датчик и хаб протечки, пожарный датчик, счётчик, телевизор, холодильник, чайник, плита, духовка и домофон.
Настройки открываются по изображению устройства. Включение и выключение
применяется сразу; настройки и сброс защиты также выполняются без подтверждения. Фильтр
Rubber Segment показывает устройства по комнатам. Squish Switch блокирует
повторные команды во время выполнения запроса.

Slosh Gauge в настройках устройств управляет яркостью света и шестью
ступенями скорости вентиляции. Изменение скорости переводит вентиляцию в ручной
режим. Настройки сохраняются автоматически: числовые поля и регуляторы — с короткой
задержкой, выбор режима — сразу. На выключенном оборудовании регуляторы недоступны. Выключенные термостат
и вентиляция не обновляют показания датчиков: до включения видны последние измерения.


Сценарии поддерживают создание, редактирование нескольких действий, удаление,
включение и изолированный прогноз на 30 секунд. Правила сохраняются в
`app/data/scenarios.json`; показания и события хранятся в памяти текущего запуска.

Новый конструктор — `frontend/src/components/ScenarioSheet.tsx`: shadcn/ui Sheet,
Glide Select, Scrub Field, Squish Switch и Animated List из бесплатного React Bits.
Он использует прежний API, поддерживает несколько действий, точный ввод,
валидацию, проверку сценария и создание в выключенном состоянии.
Для включения и выключения используются понятные подписи вместо 0/1.
Панель управляет фокусом, поддерживает Escape и полноэкранный мобильный режим.
Tailwind подключён без глобального preflight; общая тема — `premium.css`,
шрифт Play поставляется локально. `npm run typecheck` проверяет новый TypeScript.

Лаборатория находится под кнопкой настроек в шапке: перегрузка, повышение CO₂,
вечерний режим, тепло по датчику, протечка, пожар, звонок в дверь, кухня и
сброс состояний. Всё работает на эмуляторах.

После перегрузки откройте розетку: установите `Нагрузка = 900`, примените,
сбросьте защиту, затем включите розетку. Защита не сбросится, пока нагрузка
превышает лимит. При необходимости можно сбросить все эмуляторы в лаборатории.

Для телевизора: `/web/?mode=tv`. Поддерживается навигация стрелками и Enter.
APK-обёртки пока не созданы. Авторизация для публичного сервера пока не реализована.

## Интеграция Ujin

Откройте «Настройки и эксперименты» → «Подключение Ujin» или `/web/#integrations`.
Серверный адаптер `app/ujin_integration.py` входит учётной записью `employee`
в штатный API и Signal Panel. Доступы читаются из внешнего `доступы.json`
или ZIP без распаковки. Логин, пароль, токен и cookie не возвращаются клиенту.

В локальном `.env` (исключён из Git):
```
UJIN_CREDENTIALS_FILE="C:/path/to/quattrocold.zip"
UJIN_PANEL_URL=https://signal-panel.duckdns.org
UJIN_MODE=read
```
`UJIN_MODE`: `off`, `read` (только наблюдение), `sync` (отправка показаний
эмуляторов и применение доступных task-команд). Пауза между циклами — 15 секунд.
В интерфейсе можно отдельно проверить подключение, начать наблюдение/обмен
и остановить его. API: `GET /api/integrations/ujin`, `POST` с действием
`{"action":"check"}`, `{"action":"start","mode":"read|sync"}` или `{"action":"stop"}`.
При новом запуске доступы и сопоставления перечитываются из файлов.

Область работы ограничена устройствами, перечисленными в пакете доступов;
сопоставление по семействам, переопределения — в `UJIN_BINDINGS_FILE`
(образец `ujin-bindings.example.json`). Публикуются только уже существующие
сигналы. Ни устройства, ни словари, ни модель/вендор на платформе не создаются.
Параметры создания новых устройств ожидают инструкции организаторов.

Число сигналов в панели и доступность их в API показываются отдельно.
Если сигналы закрыты для команд (`r` / `state.readonly`), адаптер не объявляет
двустороннюю готовность. Публикация — штатный group JSON с `sn=ext_guid`,
`c=publish_class`, employee token и apartment_id в query; ноль передаётся
как `0.001` согласно контракту стенда. После отправки значение перечитывается
из панели: одного `error=0` недостаточно для подтверждения доставки.
Task-команды применяются только к управляемым локальным сигналам; `task_dt`
сохраняется в игнорируемом `app/data/ujin-tasks.json` для дедупликации.
Сетевые ошибки изолированы от цикла эмуляторов. Изолированные аварийные
тесты не имеют Ujin-адаптера и не отправляют аварии на платформу.

## Уведомления

Внизу экрана используется официальный React Bits SwipeToast: закрытие кнопкой,
Escape или свайпом, таймер скрытия с паузой при наведении/фокусе, поддержка
reduced motion. На компьютере видны до трёх сообщений, на телефоне — два;
остальные ждут в ограниченной очереди. Ошибки имеют приоритет.

`useHomeNotifications.js` отслеживает переходы реальных сигналов тревоги/сбоя,
потерю и восстановление соединения, новые события сценариев и их команды.
Начальная история не воспроизводится, повторный опрос не дублирует уведомления.
Активные проблемы при открытии страницы показываются. Результаты изолированных
проверок помечены «Тестовый стенд» / «Диагностика». Сообщения монтируются
внутри открытого native dialog, чтобы ошибки не скрывались за верхним слоем.

Все 15 устройств записывают серверные уведомления об операциях, изменениях настроек,
тревогах и восстановлении. Таймеры, прогрев духовки, достижение температуры,
звонок и открытие двери отслеживаются без ручной команды. Чайник различает начало
нагрева, ручную остановку и автоотключение после готовности воды.
Сайт, Telegram, API и MCP читают один журнал; короткая тревога между опросами
не теряется. Обычные изменения измерений не создают сообщений. Для CO₂ и мощности
ввода используются разные пороги тревоги и восстановления. Временно недоставленная
пачка повторяется для конкретного Telegram-подписчика без повторной отправки успешным
получателям. Подробная матрица событий: [docs/NOTIFICATIONS.md](docs/NOTIFICATIONS.md).

## Шаблоны сценариев

На странице `/web/#scenarios` кнопка «Шаблоны» открывает каталог из восьми
правил: перегрузка, протечка, пожар, вентиляция по CO₂, обогрев, охлаждение,
киновечер и звонок домофона. Фильтры: безопасность, климат, комфорт.
Выбор заполняет существующий редактор; пользователь может изменить условия
и действия, проверить их в симуляции и сохранить как новый сценарий.
Шаблоны не меняют уже сохранённые правила; одинаковые названия получают суффикс.
При отсутствии нужных устройств или сигналов соответствующий шаблон недоступен.
Каталог: `frontend/src/components/scenarioTemplates.json`.

## Тесты устройств

Отдельная страница `/web/#tests` доступна через пункт «Тесты» в навигации.
По умолчанию открыты «Аварийные ситуации»: перегрузка розетки, перегрузка
ввода кухни, пожар, утечка газа, протечка, высокий CO₂, сухой ход чайника
и отказ датчика термостата. Каждый тест показывает реальные показания
до события, реакцию, восстановление и ожидаемые/фактические результаты.
`GET /api/emergency-tests` — каталог, `POST` с `{"case":"fire"}` — один тест,
с `{}` — все восемь. Отчёт содержит временную шкалу и события правил стенда.
Исходники: `app/emergency_tests.py`.

При запуске аварийного теста открывается панель «Ход теста»: ступенчатый график
мощности, задымления, газа, CO₂, уровня воды или температуры, порог срабатывания,
текущие сигналы датчиков, реле и сирен. Перегрузка повышается постепенно;
график розетки одновременно показывает заданную нагрузку и фактическую мощность,
а отдельный показатель — накопленную энергию в кВт·ч. Протечка отображается
дискретно, без выдуманного процентного уровня воды.

Панель воспроизводит записанные отсчёты из `trace` на каждом шаге эмуляции и после
команд. `timeline[].frame` связывает контрольные этапы с записью; `visualization`
указывает основной сигнал, дополнительную кривую и порог. Значения не интерполируются.
Есть пауза, перемотка, переход к этапу и скорость 0,5×–4×. При проверке всех
аварий запись каждого теста показывается последовательно; остановка отменяет
оставшуюся очередь. К записи можно вернуться кнопкой «Посмотреть ход теста».
Компонент: `frontend/src/components/TestPlayback.jsx`.

Аварийный стенд использует отдельные стандартные экземпляры эмуляторов.
Встроенные защиты проверяются отдельно от явно подписанных тестовых правил;
сохранённые правила пользователя не запускаются и не изменяются.
Ввод кухни моделирует сумму мощностей четырёх приборов на счётчике, а
отключение при 6000 Вт выполняет правило стенда — у Counter нет своей
встроенной защиты от перегрузки. Модель `devices/gas.py` используется только
на стенде: в текущем доме из 15 устройств газового датчика пока нет.
Концентрация газа — % НКПР, CO₂ не подменяет датчик газа. Пороги модели
относятся к демонстрационному стенду.

Во вкладке «Диагностика устройств» остались проверки каждого эмулятора.
Можно проверить одно устройство, запустить все 15, остановить очередь,
посмотреть ожидаемые и фактические значения каждого шага, отфильтровать ошибки
и скачать JSON-отчёт. Результаты хранятся в памяти страницы до перехода или обновления.

`GET /api/device-tests` возвращает каталог проверок; `POST /api/device-tests`
с `{"device":"kettle_1"}` запускает тест одного устройства, с `{}` — всех.
Проверки используют реальные классы эмуляторов и путь обработки команд
на отдельных экземплярах со стандартными настройками. Они не меняют
живые устройства, историю, подтверждения, таймеры и файл сценариев.
Исходники проверок — `app/device_tests.py`.

## React Bits и MCP реестра компонентов

В проект добавлены исходники из официального реестра React Bits. Числа анимирует
CountUp; единственный общий WebGL-фон — DarkVeil; карточки подсвечивает SpotlightCard.
При `prefers-reduced-motion`, экономии трафика или слабом устройстве фон заменяется
статическим градиентом. DarkVeil приостанавливается в скрытой вкладке.
Фото устройств находятся в `frontend/public/images/`, описание генерации — рядом.

Реестр `@react-bits` прописан в `components.json`. MCP-сервер shadcn настроен в
`.mcp.json` для совместимых клиентов и локально в Codex:

```bash
codex mcp add shadcn -- npx -y shadcn@latest mcp
npm run mcp:check
```

После изменения настроек перезапустите Codex, чтобы инструменты загрузились
в новую сессию. `mcp:check` независимо выполняет настоящий stdio handshake,
запрашивает список инструментов и ищет CountUp в React Bits.

Инструкции: https://reactbits.dev/get-started/mcp и https://ui.shadcn.com/docs/mcp.
Лицензия компонентов приложена в `frontend/src/components/reactbits/LICENSE.md`.
Для совместимости сборки используется WASM-версия Rollup, зафиксированная в lockfile.

## Telegram

Бот работает через long polling и общий control plane, поэтому видит те же
устройства, сценарии и события, что web UI. `app/run.py` автоматически читает
`.env` из корня репозитория (реальные переменные окружения имеют приоритет).
Создайте файл и укажите токен. `*` открывает доступ всем чатам; вместо него можно
указать через запятую конкретные chat id. Пустое значение отключает бота.

```bash
cp .env.example .env
# TELEGRAM_BOT_TOKEN=...
# TELEGRAM_ALLOWED_CHAT_IDS=*
chmod 600 .env
python app/run.py --telegram-check   # getMe; при конкретном chat id — тестовое сообщение
python app/run.py --telegram         # backend + бот
```

Или отдельным процессом против уже запущенного backend:

```bash
python app/run.py --telegram --api-url http://127.0.0.1:8787
```

Команды:

- `/start` — главное меню и подписка этого чата на аварийные уведомления;
- `/devices`, `/device <id>`, `/status` — все 15 устройств, их показания и настройки;
- `/set <device> <signal> <value>` — немедленная команда устройству;
- `/scenarios` — просмотр, изменение, включение, выключение и удаление сценариев;
- `/newscenario` — мастер: название, условие, одно или несколько действий,
  активация после сохранения и изолированная проверка на 30 секунд;
- `/templates` — те же восемь шаблонов, что в веб-версии, с редактированием перед сохранением;
- `/scenario_on <id>` / `/scenario_off <id>` — управление сценарием;
- `/tests` — восемь аварийных тестов: перегрузка, пожар, газ, протечка и другие;
- `/diagnostics` — диагностика всех 15 устройств. Тесты выполняются на изолированном
  стенде, показывают реакцию датчиков и позволяют скачать JSON-отчёт;
- `/stats`, `/events [n]` — статистика дома и журнал с фильтрами;
- `/ujin` — состояние интеграции, проверка подключения, запуск и остановка обмена;
- `/notifications` — включить или выключить аварийные уведомления в этом чате;
- `/demo [overload|co2|evening|comfort|leak|fire|intercom|kitchen]` — лабораторный эксперимент;
- `/reset` — сброс эмуляторов;
- `/health`, `/id`, `/help`, `/cancel` — состояние API, chat id, помощь и отмена ввода.

Настройки устройств строятся из деклараций эмуляторов: режимы выбираются кнопками,
числовые значения вводятся сообщением и проверяются по допустимому диапазону.
Команды применяются сразу, как в веб-версии. Удаление сценария и сброс имеют отдельное
подтверждение. Поддерживаются простые фразы «включи свет», «яркость 45%»,
«скорость вентиляции 3». Произвольный диалог с языковой моделью не подключён.

Черновики и кнопки принадлежат пользователю внутри чата; повторные и устаревшие
действия отклоняются. Подписки и позиция long polling сохраняются локально в
`app/data/telegram-state.json`, черновики остаются в памяти до перезапуска. Аварии,
сбои, восстановление датчиков и реакции сценариев отправляются подписанным чатам.
Бот работает, пока запущены его процесс и backend. Реальные токены не добавляйте
в git: `.env` и `app/data/` исключены `.gitignore`, `.env.example` — только шаблон.

Меню, карточки всех 15 устройств, сценарии и шаблоны, тесты, статистика и аварийные
уведомления содержат фотографии из проекта. Короткий текст и inline-кнопки идут
в подписи к фото. Длинный отчёт продолжается текстовыми сообщениями без обрезки;
кнопки находятся в конце. Callback от фотографии обновляет её через
`editMessageMedia` или меняет подпись через `editMessageCaption`. Ошибка отправки
фото возвращает обычное текстовое сообщение с рабочими кнопками.

JPEG-файлы для устройств и меню включены в `app/assets/telegram/`; конвертация
изображений во время работы бота не нужна. Telegram `file_id` кешируются по хешу
содержимого в игнорируемом `app/data/telegram-state.json`, отдельно для каждого бота.

## API и MCP умного дома

Полная инструкция, примеры запросов и настройка обоих MCP-транспортов:
[`docs/API.md`](docs/API.md). Интерактивная документация — `/api/docs`,
OpenAPI 3.1 — `/api/openapi.json`, описание сервиса — `/api`.

HTTP MCP запускается отдельно и использует тот же backend:

```powershell
./.venv-mcp/Scripts/python.exe -m app.run --mcp-http --api-url http://127.0.0.1:8787
# MCP URL: http://127.0.0.1:8788/mcp
```

Пример HTTP-конфигурации: `mcp.http.example.json`.

MCP-сервер предоставляет AI-агентам состояние дома, историю, анализ энергии,
сценарии, изолированную симуляцию и подтверждаемое управление. Требуется
Python 3.11+ и зависимости из `requirements-mcp.txt`:

```bash
pip install -r requirements-mcp.txt
```

Рекомендуемый режим — подключение к уже запущенному control plane, чтобы агент
управлял тем же домом, что web UI и Telegram:

```bash
python app/run.py                                   # backend
POWER_GUARDIAN_API_URL=http://127.0.0.1:8787 \
  python app/run.py --mcp                           # MCP over stdio
```

В `.mcp.json` уже добавлен сервер `power-guardian` с этим адресом; MCP-клиент
должен использовать Python, в котором установлен `mcp`. Если backend не запущен,
используйте автономный in-process дом:

```bash
python app/run.py --mcp --local
```

Автономный режим создаёт отдельное состояние и не видит live-события backend —
это явно указано в выводе инструмента `get_health` (`transport: local`).

Инструменты: `get_home_state`, `list_devices`, `get_device_state`,
`get_recent_events`, `get_power_history`, `analyze_energy`, `list_scenarios`,
`create_scenario`, `toggle_scenario`, `delete_scenario`, `simulate_scenario`,
`request_device_command`, `confirm_device_command`, `run_demo`, `reset_home`,
`get_health`. Добавлены `get_scenario`, `update_scenario`, `list_scenario_templates`,
`create_scenario_from_template`, `list_emergency_tests`, `run_emergency_tests`,
`list_device_diagnostics`, `run_device_diagnostics`, `get_ujin_status`,
`manage_ujin_integration`, `describe_api` — всего 27 инструментов.
Ресурсы: `home://state`, `home://events`, `home://scenarios`, `home://devices`,
`home://scenario-templates`, `home://tests/emergency`, `home://tests/devices`,
`home://integrations/ujin`, `home://api`.

Опасные команды не выполняются одним вызовом: `request_device_command`
возвращает `confirmation_id`, после чего агент обязан вызвать
`confirm_device_command`. Токен живёт 60 секунд. Для stdio-режима используйте
только stderr для диагностики, чтобы не повредить протокол.

## Проверки

```bash
npm run build
npm run typecheck
python -m unittest app.tests.test_power_guardian
python -m unittest app.tests.test_home_client app.tests.test_telegram_bot app.tests.test_mcp_server
python -m unittest discover -s task/quattrocold/emulators/tests
npx playwright install chromium
npm run test:e2e
```

Если Chromium Playwright не установлен, но есть Edge, в PowerShell можно выполнить
`$env:PLAYWRIGHT_CHANNEL='msedge'` перед `npm run test:e2e`.

Браузерный тест поднимает отдельный runtime без файлового хранилища. Проверяет
изображения, управление, перегрузку и восстановление розетки, создание/симуляцию
правила, комнаты, мобильную компоновку и TV-навигацию.
