# Свой pull-клиент (язык любой) — контракт

> **Твой стенд: тест-ОАЭ** (API `https://api-uae-test.ujin.tech/api`). Все адреса в этом документе уже переведены на него; где осталось слово «preprod» (история прогонов) — читай «тест-ОАЭ». Устройства: команда запуска в брошюре (`--ust-auth`), dev-токен не нужен.

Зачем: платформа не always-push на наши устройства. Команды «вниз» надо
забирать. Три пути, в порядке доступности на хакатоне.

## Путь A. Опрос кабинета (ust) — работает уже
Эталон: `emulators/live_loop.py`.

```
цикл раз в N сек:
  GET /api/bmsdevice/get-device-info/?token=<ust>&serialnumber=<sn>
  для каждого сигнала: если signal_task_value есть и
      signal_task_dt > последнего обработанного:
     применить значение; запомнить task_dt
  отправить новые значения вверх (путь публикации ниже)
```

- `task` виден ТОЛЬКО для сигналов `mgmt != r` (словарь-авто = `r`,
  нужен довод rw — organizer-fixes п.3).
- Дедупликация по `signal_task_dt` (повторно не исполнять).
- `GET /api/devices/difference/?token=<ust>&dt=<unix>` — альтернатива:
  дельта значений всех устройств аккаунта (для витрин, не для команд).

## Путь B. HTTP-сервер на устройстве (как настоящее железо)
Платформа сама зовёт устройство по `device_first_server`:
`GET <server>/?data={"recv":[{"command":"management","id":"<serial>",
"<signal>":<value>}]}` — устройство отвечает 200. Реализовано в
`core.py:serve_forever`. Требует: доступный адрес + правка `first_server`
(орг-и) + `apartment_id>0`.

## Путь C. WebSocket (когда завели cast; organizer-fixes п.11)
Клиент: `emulators/ws_client.py`. Открой `ws://<srv>:11019/` →
auth `{"token":"<ust>","event":"authenticate","signals":true}` →
команды приходят `setValue`, отвечать не надо; эхо управления по `id`.

## Публикация значений вверх (общая для всех путей)
`POST /api/import_device/group-update-device-signal/?device-token=<dev>`
тело-JSON `{"data":[{"sn":"<ext_guid>","s":"<класс>_<имя>","v":<число>,
"c":"<класс>"}]}`.
- `0` не проходит (`empty()`) → `0.001`.
- Новый сигнал двумя запросами: сначала короткое имя (создаёт словарь),
  потом полное `<класс>_<имя>` со значением.
- **`c` — это класс МОДЕЛИ устройства, не вымышленный префикс.** Функция
  `lupsl` ищет устройство `по ext_guid + класс` и при несовпадении молча
  пишет в пустоту: `error=0`, в БД — ничего (проверено 20.10 на двух
  устройствах сразу). Для модельки хакатона это `integrations_devices`.
- Ответ смотреть: `error=0` — иначе сигнал мог не найтись молча.
- Полное имя сигнала, под который ЕЩЁ НЕТ словаря, — тоже тихая потеря:
  `error=0`, в БД пусто (замер 30.10: 2400 «успешных» пакетов, ноль строк).
  Порядок обязателен: короткое имя → словарь → полное имя со значением.
- `sn` (ext_guid) с дефисом — публикация тонет молча, тот же `error=0`
  (rehearsal-якорь `hackathon-probe-693_693`, 30.10). Titles устройств —
  без дефисов, и проверяй ext_guid после создания.

## Мини-приёмка своего pull-клиента
1. task из панели дошёл и применён ≤ N сек.
2. Повтор того же task (тот же `task_dt`) не исполнен дважды.
3. Значение `0` не ломает цикл.
4. Обрыв сети — цикл жив, восстановление без перезапуска.
5. `group-update-device-signal` принимает **только JSON-тело**
   (`Content-Type: application/json`, токен в query). Form-кодирование
   проходит в dry-run, а на живой платформе — `error` «Data is empty»
   (поймано на портах, 27.10.2026).
