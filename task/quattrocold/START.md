## Шаг 3. Выбери семейство (это и есть твой проект)

Команда одна и та же: `python main.py <семейство> --port 8099`.
У каждого семейства сигналы уже разложены по трём человеческим группам:
**📊 свойства** (что измеряю), **🎛 возможности** (чем управляю),
**⚙️ настройки** (пороги/таймеры/периоды).

| Команда | Семейство | Что показывать на демо |
|---|---|---|
| `leak` | Протечка (умный дом) | датчик мокнет → тревога → самотест |
| `barrier` | Шлагбаум/СКУД | открыл → авто-закрытие; подставь предмет — реверс |
| `thermostat` | Термостат/отопление | цель ±гистерезис: греет и отпускает |
| `ventilation` | Вентиляция (приточка) | CO2 растёт → авто-режим поднимает скорость |
| `counter` | Учёт э/в/тепло (`--resource electricity/cold/hot/heat`) | тарифы копятся; реле нагрузки отключает |
| `fire` | ПОЖС (дымовой датчик) | дым выше порога → пожар; тампер; самотест |
| `light` | Свет/реле | яркость, энергия считается, авто-выключение |
| `elevator` | Лифт | вызов → едет этаж за этажом → `floor_changed` |
| `hub` | Хаб + 3 датчика | композит: внутренняя коммутация |

Каждое устройство — один файл в `devices/` (~60 строк). Своё железо за 30 секунд:

```bash
python new_device.py valve --title "Клапан" --clone light
python main.py valve --port 8099
```

Генератор создаст файл с тремя группами сигналов и зарегистрирует его —
правь `tick()` под свою физику.

**ПРОФИТ:** у тебя есть «железо» со своей физикой — основа проекта.

## Детали по семействам (что крутить, что ждать)

Локально: `python main.py <семейство> --port 8099` → дашборд
http://localhost:8099 (там же ручное изменение сигналов). В живую — те же
сигналы в панели (`→ API` / task).

**counter (счётчик)** — `--resource electricity|cold|hot|heat`
- Крути: `report_period` (rw, настройки) — частота отчётов; `load_relay` —
  нагрузка меняет `power_w` и скорость намотки `total`.
- Жди: `total` только растёт (monotonic), тарифные зоны `kvh_t1/t2`,
  `battery` медленно садится.
- Частая ошибка: ждёшь убывания `total` — назад он не идёт: на платформе
  это control=`counter`, сырое уменьшение = «вскрытие прибора».

**ventilation (приточка)**
- Крути: `mode` (auto/manual/off), `fan_speed` (0–6 ступеней), `co2_target`.
- Жди: в auto скорость растёт, если `co2` выше `co2_target`; `supply_temp`
  греется от `heat_pct`.
- Частая ошибка: `mode=off` — скорость обнуляется и не поднимается, пока не
  вернёшь auto/manual. Это фича, не баг.

**fire (пожарный датчик)**
- Крути: задымление (на дашборде) до `threshold` (rw, по умолчанию 60).
- Жди: `smoke` растёт → `alarm=1` → событие; `tamper` — тамга снятия;
  `self_test` (w, кнопка) — самотест без задымления.
- Частая ошибка: пишешь `alarm=1` руками — физика перетирает на следующем
  тике; поднимай `smoke`, тревога выведется сама.

**light (свет)**
- Крути: `lamp` (switch), `brightness` (0–100).
- Жди: `power_w` и намотка `energy_kwh` от яркости; `offline_timeout` —
  авто-оффлайн (0=выкл).
- Частая ошибка: `brightness>0` при `lamp=0` — лампа не светит, мощность 0.

**hub (хаб + 3 датчика)**
- Крути: `mute` (rw).
- Жди: `leak` = ИЛИ по внутренним датчикам (не все на платформе!),
  `sensors_online/total`, `siren` включается сам при протечке без mute.
- Частая ошибка: ищешь датчики 1–3 в кабинете — они внутренние, наружу идёт
  одна витрина хаба (паттерн «шлюз + подчинённые»).

## Минное поле (прочитай один раз, сэкономишь 3 часа)

1. Значение `0` платформой не пишется (`empty()`) — используй `0.001` или
   спрашивай обходной путь.
2. Новый сигнал сначала создаётся коротким именем, значение — вторым запросом
   (`ujin_client.publish_group(rows, new_short=[...])` делает две фазы сам).
3. Поле `c` в публикации = **класс модели** (`integrations_devices`), не
   выдуманное имя: платформа фильтрует по классу и при несовпадении пишет
   в пустоту без ошибки (`error=0`, данных нет).
4. Автословари создаются `management='r'` — команда «вниз» не пройдёт, пока
   словарь не станет `rw` (орг-и, organizer-fixes п.2).
5. `devices/wss/` и другие ручки шлюза: параметр `token=`, не `user_token=`.
6. В команду `setValue` serial передавай числом, имя сигнала — короткое
   (`rele1`, не `myclass_rele1`).
7. Не клади токены в git — приёмка `@quality` это ловит (К-03).

| Симптом | Причина → лечение |
|---|---|
| Панель 500 на всех страницах | старый процесс держит порт, шаблоны новые → `python tools/panel_live_check.py` из корня репо (инструмент орг-ов, нужен код панели), ритуал перезапуска в `code/signal-panel/README.md` |

| Устройство создалось, в BMS/МП не видно | `apartment_id=0` (ограничение стенда, fix п.11) — покажем на панели орг-ов |
| «→ API» доходит, «👤» нет | нет `ust` в `token.txt` или сигнал `mgmt=r` (мина 3) |
| WS: «Access is denied» | sn не зарегистрирован на cast / чужая среда — это к орг-ам, не чинится с нашей стороны |
| Команда ушла, устройство молчит | pull-цикл не читает `task` (PULL-CLIENT.md, дедуп по `task_dt`) или `mgmt=r` |
